# 被AI上位了？设计师的Figma被一个Cursor插件干掉了

> 来源：[[2026-05-25-271-pencil 给 Agent 使用的 Figma.md]]

## 读者与痛点
- 目标读者：UI/UX设计师、前端开发者、独立产品人、希望快速出原型的知识工作者
- 痛点：1. 在快速迭代的环境中，从文字需求到高保真设计稿的转化速度太慢，拖累整体项目进度。 2. 设计师担心被AI工具替代，对“AI生成UI”既好奇又焦虑。 3. 开发者不想总等设计师出图，但自己用Figma又不熟练，沟通成本高。

## 新鲜观点
这不是又一个AI设计工具，而是一个信号：设计工具正在从“设计师的专属画布”演变成“开发环境的原生组件”。真正的冲突点不在于“AI能不能画好UI”，而在于“当代码编辑器内置了Figma级的生成能力，传统设计工作流和设计师的核心价值在哪里？”。

## 核心立场
“Pencil”类工具的出现，标志着“设计实现”这一环节正在被AI“产品化”和“民主化”。设计师的核心价值将加速从“画图执行”上移至“定义系统、理解用户、创造美学标准和驾驭AI工具”。会用AI生成设计的开发者，和会指挥AI生成设计的设计师，将成为新的效率枢纽。

## 钩子
- “你的Figma订阅费，可能白交了。”我最近在Cursor里装了个插件，10分钟出了5套高保真方案，同事问我什么时候成设计大神了。
- 当开发同事把一个AI生成的、和Figma一模一样的设计稿丢给我，让我‘优化一下’，我作为设计师的沉默震耳欲聋。
- 今天起，忘掉‘找设计师出图’这个步骤吧。在代码编辑器里跟AI对话，它就是你的24小时待命设计部。
- Figma十年没做到的事，一个VSCode插件做到了：让设计稿像代码一样，可以在开发环境里‘实时编译’生成。
- AI淘汰设计师？错了。它淘汰的是‘以画图为目的’的设计工作，解放的，才是真正以‘设计思维’解决问题的人。
