# 小白教程！Claude Code Task系统更新了什么？

> [AI产品自由](https://space.bilibili.com/552599364) | [BV1sJzqBkEDy](https://www.bilibili.com/video/BV1sJzqBkEDy) | 时长 3:57

## 背景介绍
- 视频由UP主成峰（来自“AI产品自由”频道）讲解，基于Claude Code团队对任务清单系统的更新。
- 核心变化：将原来的简单To do list（小备忘录）升级为完整的项目管理Task系统，以支持更复杂的任务处理。

## 升级原因
- **原To do list的局限性**：最初设计为小备忘录，用于帮助模型记忆任务，因为模型上下文窗口有限，无法记住长期任务。
- **模型能力提升**：随着模型变强，可以运行更长时间并记住更多内容，原系统变得鸡肋，小任务无需外部工具。
- **新需求驱动**：用户需要从简单任务转向复杂任务，复杂任务涉及依赖关系、多agent协作和多会话执行，原系统无法满足。

## 新Task系统概述
- **系统定位**：从简单备忘录进化为完整的编排系统，专注于复杂任务管理。
- **复杂任务的关键工具**：
  - **C-agent（子agent）**：跨窗口自动启动子agent，用于执行子任务。
  - **更大上下文窗口**：提升一次对话能记住的内容量，支持长任务。
  - **多会话协作**：允许开多个Claude Code窗口并行执行任务，提高效率。

## 关键特性详解
### 依赖关系管理
- **概念**：任务之间存在依赖关系，如任务B必须等任务A完成后才能开始，常见于复杂项目（如商城系统依赖数据库和前端页面）。
- **实现方式**：新Task系统引入关键字段管理依赖，包括：
  - **ID**：每个任务的唯一标识。
  - **任务详情**：任务内容描述。
  - **状态**：任务当前进度。
  - **依赖于什么任务**：列出前置任务。
  - **被什么任务依赖**：列出后置任务。
- **具体示例**：任务4被设置为依赖于任务3（blocker 3），只有任务3完成系统检查后，任务4的锁定才会清空，任务4才能开始执行。

### 文件系统存储与锁机制
- **存储方式**：Task系统数据存储在文件系统中，而非仅依赖模型上下文。根目录包含TaskListID，每个任务对应一个文件（如任务1、任务2等）。
- **文件锁机制**：
  - 当Agent A编辑Task文件时，会先打开一个lock文件，表示正在编辑。
  - 编辑完成后关闭lock，其他Agent（如Agent B）才能访问和编辑，避免多个agent同时操作冲突。
  - 原理：文件只能有一种编辑状态，实现排队编辑，确保数据一致性。
- **好处**：允许agent之间协调，知道前一个编辑者的内容，支持有序更新。

### 多Agent协作
- **协作模式**：子agent可以继承主agent的任务ID，实现任务自动分发和共享。
- **工作流程**：例如，规划agent分配任务给前端、后端、UI等agent，各子agent完成任务后，由主agent更新对应的TaskID，无需子agent手动修改。
- **优势**：任务列表自动共享，无需手动配置，提高多agent协作效率。

### 多会话协作
- **场景**：用户可以开多个终端窗口并行执行不同任务，加速整体进度。
- **实现方法**：启动Claude Code时，通过带参数（如`--task-list-id [ID]`）指定共享的任务列表ID，这样多个会话就能访问同一个文件夹和任务数据。
- **关键点**：通过参数确保所有会话共享同一个Task ID，协调并行任务。

## 实操示例
- **启动多会话协作**：在命令行启动Claude Code时，使用参数如“--task-list-id task_123”，其中“task_123”是共享的任务列表ID，所有会话基于此ID协作。
- **设置任务依赖**：在Task系统中，为任务4添加依赖关系，指向任务3的ID，并将任务3标记为blocker；当任务3状态变为完成后，系统自动解锁任务4。

## 总结
- Claude Code Task系统升级的核心是适应模型能力提升后的需求，通过引入依赖关系管理、文件系统存储、多agent协作和多会话协作，将简单备忘录转变为强大的项目管理工具，支持复杂任务处理，提升了工程化能力和协作效率。
