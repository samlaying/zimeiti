# AI 毁了我的代码，直到我开始TDD

## AI时代下的TDD实践指南：如何用测试驱动开发驾驭AI编码

### 1. AI在编程中的挑战
- **问题描述**：AI在开发中经常使用不熟悉的技术栈，导致生成的功能与最终需求存在偏差，且代码量庞大（如几千行），使得手动修改困难。
- **核心痛点**：AI生成的代码难以控制和维护，缺乏对需求的精确理解，容易引入错误或多余功能。

### 2. TDD简介与演变
- **定义**：TDD（测试驱动开发）是一种软件开发方法，强调在编写实现代码之前先编写测试用例。
- **传统优缺点**：
  - **优点**：迫使工程师在编码前明确需求，减少实现阶段的错误，提高代码质量。
  - **缺点**：过程费时费力，对于资源有限的项目可能不切实际。
- **AI时代的转变**：在AI时代，TDD的缺点（如耗时）不再成为障碍，因为AI可以快速生成测试代码；而优点愈发突出，因为AI经常误解需求，TDD能通过测试确保AI正确理解需求。

### 3. 使用TDD与AI结合的实操步骤
以下是完整步骤，帮助用户利用TDD有效管理AI生成的代码：

1. **明确需求并写成文档**：
   - 这是唯一不能交给AI的步骤，因为需求只有人类最清楚。
   - 避免让AI编写需求文档，防止其“幻想”出多余或不存在的功能。
   - **思考方式**：使用“given when then”结构来描述需求：
     - **Given**：给定什么前提条件。
     - **When**：发生什么动作或事件。
     - **Then**：期望什么结果或输出。
   - **示例**：一个登录验证功能的需求文档：
     - Given：数据库里存在一个用户Alice。
     - When：用户输入正确的凭据。
     - Then：返回登录成功的结果。

2. **让AI编写测试代码**：
   - 将自然语言需求（从文档中）翻译成精确的测试代码，测试代码应覆盖所有边界情况（如用户状态、加密方式等）。
   - 关键点：模糊的自然语言（如“返回登录成功”）需要具体化（如返回True、用户信息或Token，以及处理停用状态）。

3. **检查测试代码**：
   - 审查AI生成的测试代码，确保它准确反映了需求文档中的“given when then”结构。
   - 如果发现问题，修正测试代码或调整需求文档，以避免后续实现偏差。

4. **让AI按测试实现功能**：
   - 基于验证过的测试代码，指示AI编写实际的功能实现代码。
   - AI会处理技术细节（如调用哪个API），用户无需深入了解。

5. **运行测试并迭代修改**：
   - 运行测试用例，检查是否通过。
   - 如果测试失败，让AI修改实现代码，重复此过程直到所有测试通过。
   - **最终产出**：不仅得到可运行的代码，还获得有测试保障、可维护的代码库。

### 4. 核心价值与工程师角色
- **工程师的价值**：在AI时代，程序员的核心价值不再是具体的技术实现（如记忆API），而是**需求定义**和**架构设计**。
- **AI的解放作用**：AI类似于高级语言将程序员从汇编中解放出来，AI将程序员从技艺API中解放出来，使人回归本质——专注于“做什么”和“为什么做”。
- **实践意义**：TDD与AI结合，能让开发者在享受AI效率的同时，保持代码的可控性和质量，避免项目失控。

### 5. 总结与建议
- **核心要点**：在AI辅助编程中，TDD是关键工具，它通过测试确保AI准确理解需求，从而生成高质量、可维护的代码。工程师应专注于需求文档编写和测试审查，而将实现细节交给AI，这体现了技术进步下人本价值的回归。
- **实践建议**：结合经典软件工程原则（如设计模式、架构）与AI效率工具，持续学习以适应AI时代，UP主的知识星球提供相关资源，帮助开发者提升技能。
